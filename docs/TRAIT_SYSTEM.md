# 特质专属选项机制

## 玩家看到的规则

- 拥有某些特质时，合适的旧事件里可能多出一个带特质名称的选项。
- 每个事件最多出现一个专属选项；不选也能正常继续。
- 经常选择某个特质的做法，可能让它升级或产生隐藏变化。

第一份完整样板是“癫佬”：它只在有当前 NPC 的社交场景出现。普通阶段的关系结果有好有坏；第四次使用时解锁“古明地恋”，此后选项更跳脱，但别人会自然接受，关系结果也更偏向积极。

## 后台怎样工作

```text
旧事件选项 + 当前场景标签
          ↓
检查玩家特质、等级、冷却和最近选项
          ↓
至多追加一个专属选项
          ↓
玩家选择后结算关系、经验与隐藏解锁
```

关键文件：

- `src/data/trait-choices.js`：选项文字、最低等级、允许场景和进化条件。
- `src/core/trait-system.js`：触发、保底、防重复、成长与结果结算。
- `src/core/ui.js`：把专属选项与原事件选项一起显示。
- `src/core/game.js`：为允许触发的事件提供 `tags`、`npc` 和稳定的 `eventId`。

## 给其他特质增加专属选项

优先在 `TRAIT_CHOICE_SETS` 中增加一组规则。不要在几十个事件里分别写 `if (hasTrait(...))`。

一组规则至少需要：

```js
{
  id:"规则的唯一名称",
  trait:"开局特质名称",
  resolver:"效果处理器名称",
  requiredTags:["需要的场景标签"],
  offerChance:0.55,
  choices:[
    {id:"选项唯一名称",minLevel:1,label:"按钮文字",result:"行为结果"}
  ]
}
```

如果新特质只是改变属性或关系，可以复用已有处理思路；如果它有完全不同的结果，再在 `TRAIT_CHOICE_RESOLVERS` 中增加一个集中处理器。

## 当前约束

- 只有 NPC 社交事件接入了该机制，考试、总结和重大路线选择不会触发。
- 初始池暂时固定包含“癫佬”，方便试玩本次样板；机制稳定后可恢复完全随机。
- 关系仍是单一数值，尚未拆分为熟悉、信任、友情或恋爱。
