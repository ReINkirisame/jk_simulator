# 当前代码结构

## 页面加载顺序

`index.html` 最下方按以下顺序加载脚本：

1. `traits.js`、`npcs.js`：基础内容。
2. `state.js`：创建游戏状态 `S` 和通用工具。
3. `ui.js`：创建界面渲染函数。
4. 各事件数据文件：固定事件、路线、随机事件和考试题面。
5. `game.js`：使用前述数据运行月份、NPC、考试和假期流程。
6. `main.js`：检查数据并初始化页面。

目前使用传统浏览器脚本而不是打包工具，因此可以直接双击 `index.html`。脚本顺序属于依赖关系，不要随意调整。

## 核心状态

`src/core/state.js` 中的 `S` 是当前唯一游戏状态，主要包含：

- 姓名、月份、学期和阶段；
- 四项属性；
- 初始特质和后天兴趣；
- 社团、路线与分科；
- 已认识的 NPC 和关系值；
- 已使用事件、历史、旗标和考试成绩。

将来加入存档时，应保存并恢复 `S`，不要从页面文字反推数据。

## 事件选项格式

现有事件继续沿用三项数组：

```js
[
  "按钮上显示的文字",
  "效果函数没有返回文字时显示的默认结果",
  () => {
    // 修改状态，并可返回另一段结果文字
    return "最终显示的结果";
  }
]
```

通用显示函数位于 `src/core/ui.js` 的 `showChoices()`。

这一格式兼容原草稿，但不适合无限扩张。完成九、十月纵向样板时，建议再设计带 `id`、`conditions`、`effects` 和 `next` 的对象式事件格式；不要在此次文件拆分中同时迁移全部旧事件。

## 游戏主流程

当前普通月份大致为：

```text
固定事件 → 路线事件 → 生日事件 → 认识 NPC → 随机事件 → 下个月
```

十二月、考试、社团选择和寒假存在特殊桥接，集中在 `src/core/game.js`。

## 调试入口

在浏览器打开游戏后按 `F12`，在 Console 中可以使用：

```js
GameDebug.version
GameDebug.getState()
GameDebug.validate()
```

它们分别查看版本、复制当前状态和重新检查事件数据。

## 当前有意保留的限制

- 仍然只有高一内容。
- 属性成长和选择后果尚未系统化。
- NPC 还是称号而非正式角色姓名。
- 尚无存档、恋爱线、多结局和调试面板。
- 考试选项尚不判断正确与否。

这些属于后续设计任务，不是本次拆文件造成的缺失。
