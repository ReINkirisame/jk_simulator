# 当前代码结构

## 页面加载顺序

`index.html` 最下方按以下顺序加载脚本：

1. `traits.js`、`npcs.js`、`trait-choices.js`：基础内容与特质选项规则。
2. `state.js`：创建游戏状态 `S`、统一随机源和通用状态工具。
3. `check-system.js`：执行 2d6 判定并生成结果说明。
4. `trait-system.js`：判断场景、注入选项并结算特质成长。
5. `ui.js`：创建界面渲染函数。
6. 各事件数据文件：固定事件、路线、随机事件和考试策略。
7. `game.js`：使用前述数据运行月份、NPC、考试和假期流程。
8. `main.js`：检查数据并初始化页面。

目前使用传统浏览器脚本而不是打包工具，因此可以直接双击 `index.html`。脚本顺序属于依赖关系，不要随意调整。

## 核心状态

`src/core/state.js` 中的 `S` 是当前唯一游戏状态，主要包含：

- 姓名、月份、学期和阶段；
- 四项属性；
- 初始特质和后天兴趣；
- 社团、路线与分科；
- 已认识的 NPC 和关系值；
- 特质经验、隐藏特质和最近用过的专属选项；
- 已使用事件、历史、旗标和考试成绩；
- 人物倾向、选择记录、重要记忆、判定记录与 NPC 印象。

将来加入存档时，应保存并恢复 `S`，不要从页面文字反推数据。

## 事件选项格式

现有事件继续沿用数组格式，并允许第四项稳定元数据：

```js
[
  "按钮上显示的文字",
  "效果函数没有返回文字时显示的默认结果",
  action => {
    // 修改状态，并可返回另一段结果文字
    return "最终显示的结果";
  },
  {
    id:"stable-choice-id",
    tags:["主动","社交"],
    impact:"用于日志与人物小结的影响说明"
  }
]
```

通用显示函数位于 `src/core/ui.js` 的 `showChoices()`。效果函数收到的 `action.next` 可以交给考试等接管界面的子流程，结束后再准确回到原事件，而不必手工猜测事件位置。

固定事件还可以使用 `getChoices()` 在显示时生成选项，例如国庆节只列出本局已经认识的 NPC。`runFixedMonth()` 会统一记录事件 ID、选项 ID、倾向标签和影响说明。

`showChoices()` 还可以接收事件环境：

```js
{
  allowTraitChoices:true,
  tags:["npc","social"],
  npc:"中二病",
  eventId:"npc-talk:高一上:10:中二病"
}
```

界面会把普通选项和环境交给 `injectTraitChoices()`。它最多追加一个符合条件的特质选项，因此以后增加别的特质时不需要修改每一个旧事件。

这一格式兼容原草稿。九、十月已经具有稳定事件 ID、选项 ID、条件、动态选项和持久影响；其余旧事件仍可逐月迁移，不要一次重写整个高一。

## 统一判定

`resolveCheck()` 位于 `src/core/check-system.js`：

```text
2d6 + 属性修正 + 特质/准备/情境修正 - 难度
```

结果分为大失败、小失败、普通成功和特别成功。正常内容只通过 `gameRandom()`、`randomInt()` 和 `randomItem()` 获取随机值，不应散落新的 `Math.random()`。

## 游戏主流程

当前普通月份大致为：

```text
固定事件 → 路线事件 → 生日事件 → 认识 NPC → 随机事件 → 下个月
```

十二月、考试、社团选择和寒假存在特殊桥接，集中在 `src/core/game.js`。

## 调试入口

在浏览器打开游戏后按 `F12`，在 Console 中可以使用：

```js
GameDebug.version
GameDebug.getState()
GameDebug.validate()
GameDebug.check({difficulty:8,dice:[3,4]})
```

它们分别查看版本、复制当前状态、重新检查事件数据，以及用指定骰点检查判定结果。

## 当前有意保留的限制

- 仍然只有高一内容。
- 九、十月已接入选择后果；十一月以后仍有大量旧事件需要迁移。
- NPC 还是称号而非正式角色姓名。
- 尚无存档、恋爱线、多结局和调试面板。
- 考试采用整体策略与临场判定，不模拟逐科题目正确与否。

这些属于后续设计任务，不是本次拆文件造成的缺失。
