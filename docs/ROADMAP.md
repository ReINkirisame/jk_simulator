- [ ] 为事件建立稳定 ID

- [ ] 正式命名核心 NPC
- [ ] 设计熟悉、信任、好感与关键事件

- [ ] 使用浏览器本地存档

## 0.5：完成高一

- [ ] 将现有高一内容迁移到新事件结构
- [ ] 补齐校园生活、体育等路线
- [ ] 重做考试选择与成绩逻辑
- [ ] 控制每月事件数量和单局总点击数

## 0.6 以后

- 高二：路线深化、关系冲突和群像。
- 高三：时间压力、取舍、告别和毕业。
- 组合式多结局。
- 视觉、立绘、音效和移动端体验。

## 暂时不要同时做

- 不要一边迁移事件格式，一边批量生成高二文本。
- 不要在存档格式未确定前写大量依赖存档的机制。
- 不要为了“像正式游戏”过早引入大型框架。
- 不要让一次 Pull Request 同时修改界面、底层规则和几十个事件。
